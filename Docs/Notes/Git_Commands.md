# Git — довідник команд і журнал того, що застосовувалось

Довідник за принципом **"хочу X → яка команда → що кожен символ у ній означає"**. Кожен
розділ самодостатній. Наприкінці — **журнал**: які саме команди й коли реально
застосовувались у цьому репозиторії (поповнюється з кожною новою командою).

Версія: `git version 2.46.0.windows.1`. Увесь вивід нижче — **реальний**, знятий з цього
репозиторію (а не вигаданий приклад).

## 0. Як читати команду git

```
git  restore  --source=main  --staged  --worktree  --  .claude  Docs
│    │        │              │          │           │   └──────┴── аргументи: шляхи (файли/теки)
│    │        │              │          │           └── «далі тільки шляхи, не опції»
│    │        └──────────────┴──────────┴── опції (прапорці): як саме виконати
│    └── підкоманда: що зробити
└── програма
```

### Символи

| Символ | Приклад | Що означає |
|---|---|---|
| `-` (одна риска) + **одна літера** | `-c`, `-m`, `-u` | коротка опція. Короткі можна склеювати: `-am` = `-a -m` |
| `--` (дві риски) + **слово** | `--staged`, `--stat`, `--oneline` | довга опція, той самий сенс, але читабельне ім'я |
| `--опція=значення` | `--source=main` | опція зі значенням. Іноді можна через пробіл: `--source main` |
| `--` **окремо**, з пробілами по боках | `git restore -- Docs` | **роздільник**: усе праворуч — шляхи до файлів, навіть якщо ім'я схоже на гілку чи опцію. Без нього git може сплутати теку `main` з гілкою `main` |
| `"..."` | `git commit -m "Add jump"` | лапки: текст із пробілами — **один** аргумент. Без лапок `Add` і `jump` стали б двома різними аргументами |
| `.` | `git add .` | поточна тека (і все всередині, рекурсивно) |
| `<...>` | `git switch -c <ім'я> <хеш>` | **не пишеться**: так у документації позначають місце, куди підставити своє значення. Пишеш `git switch -c phisicsPractice 09de855` |
| `[...]` | `git log [<хеш>]` | **не пишеться**: позначка "необов'язкова частина" в документації |
| `гілка:шлях` | `git show main:Docs/SESSION_NOTES.md` | двокрапка: "файл за цим шляхом, **у тому вигляді, як він є в гілці/коміті** зліва". Нічого не перемикає, лише показує |
| `HEAD` | `git log HEAD` | "де я зараз": останній коміт поточної гілки |
| `~N` | `HEAD~1`, `HEAD~3` | на N комітів назад від вказаного. `HEAD~1` — передостанній |
| `^` | `HEAD^` | те саме, що `~1` (батьківський коміт) |
| `@{N}` | `HEAD@{1}` | N-й запис у `reflog` (де HEAD був N кроків тому). **У PowerShell бери в лапки:** `'HEAD@{1}'` — бо `{}` там означає блок коду |
| `a..b` | `git log main..phisicsPractice` | коміти, які є в `b`, але немає в `a` |
| хеш | `09de855` | ім'я коміту. Повний — 40 символів, але досить перших 7 |
| `origin` | `git push origin main` | ім'я віддаленого репозиторію (GitHub). Подивитись: `git remote -v` |

### Три місця, де живуть зміни (потрібно, щоб розуміти `--staged` / `--worktree` / `--cached`)

| Місце | Інша назва | Що це | Яка опція його стосується |
|---|---|---|---|
| Робоча тека | working tree | файли на диску, які відкриває Unity/IDE | `--worktree` |
| Індекс | staging area, "stage" | "чернетка наступного коміту": що піде в коміт | `--staged` = `--cached` (синоніми) |
| Репозиторій | історія | коміти | — |

Шлях зміни: **диск → `git add` → індекс → `git commit` → історія**.

## Мапа задач

| Хочу | Команда | Розділ |
|---|---|---|
| Подивитись, що змінено і що піде в коміт | `git status` | 1 |
| Подивитись історію | `git log --oneline` | 2 |
| Подивитись усі переміщення HEAD (навіть "загублені") | `git reflog` | 2 |
| Побачити різницю | `git diff`, `git diff --cached`, `git diff --stat A B` | 3 |

| Перейти в іншу гілку | `git switch <ім'я>` | 5 |
| Подивитись гілки і їх зв'язок із GitHub | `git branch -vv` | 5 |
| Забрати файли/теки з іншої гілки, не зливаючи гілки | `git restore --source=<гілка> --staged --worktree -- <шляхи>` | 6 |
| Скасувати незакомічені зміни у файлі | `git restore <шлях>` | 6 |
| Прибрати файл з індексу (але залишити зміни на диску) | `git restore --staged <шлях>` | 6 |
| Додати зміни в індекс | `git add <шлях>` / `git add .` | 7 |
| Зробити коміт | `git commit -m "Назва" -m "Опис"` | 7 |
| Відправити на GitHub | `git push`, вперше: `git push -u origin <гілка>` | 8 |
| Новий репозиторій з нуля | `git init` → `git remote add` → `git push -u` | 9 |

## 1. `git status` — що зараз відбувається

```
git status
```

Реальний вивід (гілка `phisicsPractice`, усе закомічено й відправлено):

```
On branch phisicsPractice
Your branch is up to date with 'origin/phisicsPractice'.

nothing to commit, working tree clean
```

| Рядок | Значення |
|---|---|
| `On branch phisicsPractice` | ти зараз у цій гілці |
| `up to date with 'origin/phisicsPractice'` | твоя гілка і її копія на GitHub однакові |
| `working tree clean` | на диску немає незакомічених змін |

Корисна опція: `git status --short` (`-s`) — по рядку на файл: `M` змінено, `A` додано,
`D` видалено, `??` git про файл ще не знає. Ліва колонка — індекс, права — диск.

## 2. `git log` і `git reflog` — історія

```
git log --oneline -4
```

- `--oneline` — один коміт = один рядок (короткий хеш + назва).
- `-4` — лише 4 останні. (Число після риски тут — кількість, не літера-опція.)

```
5a69aea Sync skills, docs and BootstrapState cleanup from main
09de855 Remove unused Move.performed subscription from InputService
63b0130 Spawn Player and wire PlayerController via Construct
51130f9 Spawn Player prefab from GameLoopState via IAssetProvider
```

Інші корисні форми:

| Команда | Що показує |
|---|---|
| `git log --oneline main..phisicsPractice` | коміти, що є в `phisicsPractice`, але немає в `main` |
| `git log --oneline -- Docs/SESSION_NOTES.md` | лише коміти, які змінювали цей файл (`--` = далі шлях) |
| `git log -1 --stat` | останній коміт + список змінених у ньому файлів |
| `git log --oneline --graph --all` | усі гілки деревом |

`git reflog` — журнал **усіх** переміщень HEAD: коміти, перемикання гілок. Рятує, коли
"загубився" коміт. Реальні рядки:

```
5a69aea HEAD@{2026-10-03}: commit: Sync skills, docs and BootstrapState cleanup from main
09de855 HEAD@{2026-09-30}: checkout: moving from main to phisicsPractice
```

## 3. `git diff` — різниця

| Команда | Що з чим порівнює |
|---|---|
| `git diff` | диск ↔ індекс (що змінено, але ще не `add`) |
| `git diff --cached` (= `--staged`) | індекс ↔ останній коміт (що піде в коміт) |
| `git diff A B` | коміт/гілка `A` ↔ коміт/гілка `B` |
| `git diff A B -- <шлях>` | те саме, але лише для цих файлів |
| `... --stat` | замість рядків коду — лише список файлів і кількість змін |

Реальний приклад (що змінилось у скілах і ROADMAP між базою гілки та `main`):

```
git diff --stat 09de855 main -- Docs/ROADMAP.md .claude
```
```
 .claude/skills/explain-formula/SKILL.md | 71 +++++++++++++++++++++++++++++++++
 .claude/skills/petpet-mentor/SKILL.md   | 24 +++++++++++
 Docs/ROADMAP.md                         |  3 +-
 3 files changed, 97 insertions(+), 1 deletion(-)
```

`+` — додані рядки, `-` — видалені. `3 +-` = зміни в 3 рядках, тобто і додавання, і видалення.

**Пастка:** `git diff --cached --stat A B` — помилка (`usage: git diff ...`): `--cached`
порівнює індекс, а `A B` — два коміти; разом не можна. Або одне, або інше.

## 4. `git show` — показати коміт або файл з іншої гілки

| Команда | Що показує |
|---|---|
| `git show <хеш>` | що змінив цей коміт |
| `git show main:Docs/SESSION_NOTES.md` | вміст файлу, як він є в `main` — **без** перемикання гілки |

```
git show main:Docs/ROADMAP.md
```
```
# petPet — 3D Third-Person Shooter. Дорожня карта
...
```

Шлях після `:` — від кореня репозиторію, через `/`.

## 5. Гілки: `git switch`, `git branch`

| Команда | Що робить |
|---|---|
| `git switch <ім'я>` | перейти в наявну гілку |
| `git switch -c <ім'я>` | **c**reate: створити нову гілку від поточного коміту і перейти в неї |
| `git switch -c <ім'я> <хеш>` | створити нову гілку **від указаного коміту** і перейти в неї |
| `git branch` | список локальних гілок (`*` — поточна) |
| `git branch -vv` | те саме + останній коміт + до якої гілки на GitHub прив'язана |

```
git branch -vv
```
```
  main            1741e25 [origin/main] Docs: lesson 04 step 6 explanation, session notes update:
* phisicsPractice 5a69aea [origin/phisicsPractice] Sync skills, docs and BootstrapState cleanup from main
```

`[origin/main]` — "upstream": куди йде `git push` без аргументів. `-v` = verbose
(детально), `-vv` — ще детальніше.

`git checkout <ім'я>` — старіша команда, що вміє і перемикати гілки, і відновлювати файли.
`switch` (гілки) і `restore` (файли) — новіші, розділені версії; `reflog` досі пише
`checkout:`, навіть коли ти перемикався через `switch`.

**Перед перемиканням** зроби коміт (або перевір `git status`): незакомічені зміни, що
конфліктують з іншою гілкою, не дадуть перемкнутись.

## 6. `git restore` — повернути файли

```
git restore --source=main --staged --worktree -- .claude Docs Assets/CodeBase/Infrastructure/States/BootstrapState.cs
```

| Частина | Значення |
|---|---|
| `--source=main` | звідки брати вміст файлів: з гілки `main` (можна хеш). Без цієї опції береться з індексу/HEAD |
| `--staged` | записати в індекс |
| `--worktree` | записати на диск |
| обидві разом | файл одразу і на диску, і готовий до коміту — лишається тільки `git commit` |
| `--` | далі — шляхи |
| `.claude Docs ...` | які файли/теки. Теку бере рекурсивно |

Гілку при цьому **не** перемикаєш і гілки **не** зливаєш — просто копіюєш вміст указаних
шляхів. Все інше (наприклад, `PlayerController.cs`) лишається як було.

Інші форми:

| Команда | Що робить |
|---|---|
| `git restore <шлях>` | викинути незакомічені зміни у файлі (повернути до стану з індексу). **Зміни втрачаються** |
| `git restore --staged <шлях>` | прибрати з індексу (протилежне `git add`); на диску зміни лишаються |

## 7. `git add` і `git commit`

| Команда | Що робить |
|---|---|
| `git add <шлях>` | додати зміни файлу в індекс |
| `git add .` | додати **усі** зміни в поточній теці (рекурсивно) — дивись `git status` перед цим |
| `git commit -m "Назва"` | коміт з того, що в індексі. `-m` = **m**essage |
| `git commit -m "Назва" -m "Опис"` | друге `-m` — окремий абзац (опис під назвою) |
| `git commit` (без `-m`) | відкриє текстовий редактор для повідомлення |

## 8. `git push` — відправити на GitHub

| Команда | Що робить |
|---|---|
| `git push -u origin <гілка>` | вперше для нової гілки: відправити і запам'ятати зв'язок. `-u` = `--set-upstream` |
| `git push` | наступні рази: git уже знає, куди (з `-u`) |
| `git remote -v` | які віддалені репозиторії підключені |

```
git remote -v
```
```
origin	https://github.com/vid66-source/petPet_Project.git (fetch)
origin	https://github.com/vid66-source/petPet_Project.git (push)
```

## 9. Новий репозиторій з нуля

| Команда | Що робить |
|---|---|
| `git init` | зробити поточну теку git-репозиторієм |
| `git branch -M main` | перейменувати поточну гілку в `main`. `-M` = перейменувати **примусово**, навіть якщо `main` вже є (`-m` — без примусу) |
| `git remote add origin <url>` | підключити GitHub-репозиторій під ім'ям `origin` |
| `git push -u origin main` | перша відправка |
