# Рух об'єктів: `transform`, `CharacterController`, `Rigidbody` — довідник за задачами

Це не інструкція до уроку 04 і не готовий розв'язок: у файлі **немає** повного
`PlayerController`, немає готового стрибка. Це довідник за принципом **"хочу зробити X →
який підхід, ключовий API, що з ним відбувається"**. Кожен розділ самодостатній.

Версія Unity проєкту — **2022.3.62f2**: у цій версії `Rigidbody.velocity` і
`Rigidbody.drag` (у Unity 6 вони перейменовані на `linearVelocity` і `linearDamping`).
Виводу консолі тут немає навмисно: це API рушія, поза Unity не запускається; поведінка
описана за офіційною документацією (Unity Manual → "Character Controllers", "Rigidbody";
Scripting API → `CharacterController`, `Rigidbody`, `ForceMode`, `Physics`).

## Мапа задач

| Хочу | Підхід | Ключовий API | Колізії зі світом | Хто власник позиції | Розділ |
|---|---|---|---|---|---|
| Просто перемістити об'єкт (камера, UI, ефект, телепорт) | `transform` | `transform.position`, `Translate` | **немає** | твій код | 1 |
| Рухати персонажа з колізіями, керуючи повністю сам | `CharacterController` | `Move(Vector3)`, `SimpleMove(Vector3)` | є, автоматично | твій код | 2 |
| Дати рушію рахувати рух: сила, інерція, відскок, штовханина | `Rigidbody` (не кінематичний) | `AddForce`, `velocity` | є, фізичні | фізичний рушій | 3 |
| Рухати вручну, але щоб об'єкт штовхав інші фізичні тіла (платформа, двері) | `Rigidbody` + `isKinematic` | `MovePosition`, `MoveRotation` | штовхає, сам не штовхається | твій код | 3 |
| Знати, чи персонаж стоїть на землі | залежить від підходу | `CharacterController.isGrounded` / `Physics.CheckSphere`/`Raycast` | — | — | 2, 3 |
| Реагувати на зіткнення | залежить від підходу | `OnControllerColliderHit` / `OnCollisionEnter` / `OnTriggerEnter` | — | — | 2, 3 |

## 1. `transform` — рух без фізики

`transform.position`/`Translate` просто виставляють нові координати. Рушій не перевіряє,
чи там щось стоїть.

```csharp
// об'єкт пройде крізь стіну і підлогу — колізій тут немає
transform.position += direction * speed * Time.deltaTime;
```

Підходить для того, чого фізика не стосується: камера, елементи UI, візуальні ефекти,
телепорт у задану точку. **Для персонажа, який ходить по рівню, — не підходить.**

## 2. `CharacterController`

**Що це.** Компонент-капсула, який сам є колайдером, але **не є фізичним тілом** (на об'єкті
не має бути `Rigidbody`). Не падає і не штовхається сам. Рухається лише через виклики, які
ти робиш у коді. Колізії зі світом обробляє автоматично: не дасть пройти крізь стіну,
піднімається на невеликі сходи, може ковзати схилом.

### API

| Задача | API | Повертає | Примітка |
|---|---|---|---|
| Зсунути персонажа на задану відстань | `Move(Vector3 motion)` | `CollisionFlags` | `motion` — **зсув за кадр**, а не швидкість; множити на `Time.deltaTime`. Гравітацію **не** застосовує |
| Рух зі швидкістю, гравітація вбудована | `SimpleMove(Vector3 speed)` | `bool` (чи на землі) | Вісь Y ігнорується → стрибок цим методом неможливий; швидкість в одиницях за секунду |
| Чи торкався землі під час останнього `Move` | `isGrounded` | `bool` | Відображає результат **останнього** `Move`/`SimpleMove` |
| З якими боками щось зіткнулось | значення `CollisionFlags` | flags | `Below`, `Above`, `Sides` |
| Реальна швидкість після останнього руху | `velocity` | `Vector3` | Лише читання |
| Форма капсули | `height`, `radius`, `center` | `float`/`Vector3` | Центр — в локальних координатах |
| Найкрутіший схил, на який можна підійти | `slopeLimit` | `float` (градуси) | За замовчуванням 45 |
| Найвища сходинка, яку персонаж переступить | `stepOffset` | `float` | За замовчуванням 0.3 |
| "Товщина шкіри" — зазор для колізій | `skinWidth` | `float` | За замовчуванням 0.08 |
| Мінімальний зсув, нижче якого рух ігнорується | `minMoveDistance` | `float` | За замовчуванням 0.001 |

```csharp
// зсув за кадр і перевірка, чи упиралась капсула знизу в поверхню
CollisionFlags flags = _controller.Move(displacement);
bool touchedBelow = (flags & CollisionFlags.Below) != 0;
```

### Зіткнення й тригери

- `OnCollisionEnter/Stay/Exit` для `CharacterController` **не викликаються**. Замість них —
  `OnControllerColliderHit(ControllerColliderHit hit)`, який викликається, коли контролер
  вдарився об колайдер під час `Move`. У `hit` є `collider`, `gameObject`, `normal`,
  `moveDirection`.
- Тригер-колайдери на `CharacterController` реагують: `OnTriggerEnter` спрацьовує (підбір
  предметів, зони).
- `CharacterController` **не штовхає** `Rigidbody` сам — якщо це потрібно, реалізуєш у
  `OnControllerColliderHit`.

### Що не робить за тебе

- Не застосовує гравітацію (крім `SimpleMove`). Вертикальну швидкість і падіння ти
  обчислюєш сам і додаєш до зсуву в `Move`.
- Не знає про "стрибок" — це лише твій зсув угору, який ти рахуєш.

## 3. `Rigidbody`

**Що це.** Справжнє фізичне тіло: гравітація, тертя, інерція, зіткнення обробляє фізичний
рушій за фіксованими кроками. Ти не задаєш позицію, а прикладаєш силу чи швидкість.

### API

| Задача | API | Примітка |
|---|---|---|
| Прикласти силу | `AddForce(Vector3, ForceMode)` | Один з чотирьох `ForceMode`, див. нижче |
| Виставити швидкість напряму | `velocity` (2022.3) | Обходить сили; у Unity 6 — `linearVelocity` |
| Рухати кінематичне тіло | `MovePosition(Vector3)`, `MoveRotation(Quaternion)` | Працює з `isKinematic = true`, застосовується на кроці фізики |
| Вимкнути/увімкнути фізику руху | `isKinematic` | Кінематичне: не реагує на сили, але штовхає інші тіла |
| Гравітація | `useGravity` | |
| Опір повітря | `drag` (2022.3) | У Unity 6 — `linearDamping` |
| Заборонити перекидання | `constraints = RigidbodyConstraints.FreezeRotation` | Інакше капсулу перекидає |
| Згладити рух між фізичними кроками | `interpolation = RigidbodyInterpolation.Interpolate` | Прибирає "тремтіння" візуалу |
| Не пролітати крізь тонкі стіни на швидкості | `collisionDetectionMode` | `Discrete` / `Continuous` / `ContinuousDynamic` / `ContinuousSpeculative` |

### `ForceMode` — чотири режими `AddForce`

| Режим | Дія | Враховує масу |
|---|---|---|
| `Force` | безперервна сила (кожен фізичний крок) | так |
| `Acceleration` | безперервне прискорення | ні |
| `Impulse` | миттєвий поштовх (наприклад, стрибок) | так |
| `VelocityChange` | миттєва зміна швидкості | ні |

```csharp
_rigidbody.AddForce(force, ForceMode.Impulse);                         // миттєвий поштовх
_rigidbody.MovePosition(_rigidbody.position + displacement);           // кінематичне тіло
```

### Правила роботи з фізикою

- Фізичний код — у `FixedUpdate`, не в `Update`. Крок фізики за замовчуванням 0.02 с
  (Project Settings → Time → Fixed Timestep), а кадри йдуть у нерегулярному ритмі.
- Ввід зчитується в кадрі (`Update` чи подія Input System), а прикладання сили —
  на кроці фізики. Ці дві частини між собою узгоджуєш ти.
- `transform.position` на **не**кінематичному `Rigidbody` не виставляй: це телепорт, що
  ламає інтерполяцію і фізику. Для переміщення — `rb.position`/`MovePosition`.
- Чи стоїть тіло на землі, сам `Rigidbody` не знає. Звичайний шлях — запит до фізики:
  `Physics.CheckSphere`, `Physics.Raycast`, `Physics.SphereCast` (шар землі задають через
  `LayerMask`).
- Зіткнення: `OnCollisionEnter/Stay/Exit`, тригери: `OnTriggerEnter/Stay/Exit`.

## 4. Порівняння

| Критерій | `transform` | `CharacterController` | `Rigidbody` |
|---|---|---|---|
| Хто власник позиції | ти | ти | фізичний рушій |
| Колізії зі світом | немає | є | є |
| Гравітація | немає | ти сам (крім `SimpleMove`) | вбудована |
| Стоїть на землі | — | `isGrounded` | свій запит (`Raycast`/`CheckSphere`) |
| Сходи й схили | немає | вбудовано (`stepOffset`, `slopeLimit`) | пишеш сам, капсула чіпляється за ребра |
| Миттєва зупинка й точна швидкість | так | так | ні (інерція, тертя), доводиться боротись |
| Реакція на вибух/штовханину | немає | лише якщо напишеш | природна |
| Коли рахується | будь-коли | у `Move` | на кроці фізики (`FixedUpdate`) |
| Колбеки зіткнень | — | `OnControllerColliderHit`, `OnTriggerEnter` | `OnCollision*`, `OnTrigger*` |

## 5. Що обирати (best practice)

- **Гравець шутера/екшену, керований клавішами** — `CharacterController` (або власний
  кінематичний контролер). Причина: потрібні миттєва відповідь на ввід і точна швидкість,
  а не інерція. Існують і сторонні кінематичні контролери, коли вбудованого не вистачає
  (складні схили, рухомі платформи).
- **Речі, для яких фізичність — сам геймплей** (транспорт, м'ячі, ящики, ragdoll) —
  `Rigidbody`.
- **Рухома платформа чи двері, що мають штовхати інші тіла** — кінематичний `Rigidbody`
  (`isKinematic`) із `MovePosition`.
- **Камера, UI, ефекти** — `transform`.
- **Ворог із `NavMeshAgent`** — рухає агент; якщо потрібен `Rigidbody`, роби його
  кінематичним, щоб не було двох "власників" позиції.
- **Не змішуй** `CharacterController` і некінематичний `Rigidbody` на одному об'єкті — два
  рушії руху воюють між собою.

## 6. Типові пастки

| Симптом | Причина | Як виправити |
|---|---|---|
| Персонаж застрягає, дивно поводиться, подвійні події | На примітиві Capsule залишився власний `CapsuleCollider` поруч із `CharacterController` | Видалити `CapsuleCollider`: контролер сам є колайдером |
| Після `transform.position = x` персонаж лишається на старому місці | Увімкнений `CharacterController` перезаписує позицію | На час телепорту вимкнути контролер (`enabled = false`), виставити позицію, увімкнути; або `Physics.SyncTransforms()` |
| Персонаж рухається різно швидко залежно від FPS | У `Move` передано швидкість без `Time.deltaTime` | `Move` приймає зсув за кадр |
| `isGrounded` то `true`, то `false` на рівній підлозі | Він відображає результат лише останнього `Move`; якщо зсуву вниз нема, контакту з підлогою "нема" | Перевіряти на кроці, де `Move` викликається щокадру, а не виводити зі стану вчорашнього кадру |
| Персонаж падає крізь підлогу при спавні | Капсула створена нижче поверхні підлоги | Низ капсули (`позиція.y + center.y − height/2`) має бути не нижче за підлогу |
| `Rigidbody`-персонажа перекидає | Не заморожено обертання | `constraints = FreezeRotation` |
| `Rigidbody` "тремтить" на екрані | Рух у `FixedUpdate`, візуал у `Update`, без інтерполяції | `interpolation = Interpolate` |
| Швидка куля/об'єкт пролітає крізь тонку стіну | `collisionDetectionMode = Discrete` | `Continuous` або `ContinuousDynamic` |
| Фізика працює по-різному на різних комп'ютерах | Прикладання сил у `Update` | Переносити у `FixedUpdate` |
